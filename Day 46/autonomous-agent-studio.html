🧠
Planner
Receives the user's plain-English task description and produces a structured implementation plan: inputs/outputs, sub-tasks, data structures, constraints, and an explicit list of edge cases that must be handled. This plan becomes the shared contract that all downstream agents work from.
⚙️
Executor
Takes the Planner's structured plan and writes the first complete, runnable implementation. On subsequent passes the Executor is bypassed — the Improver handles rewrites. The Executor focuses on clean, idiomatic code that covers the nominal path.
📊
Evaluator
Scores the current code draft on a 0–100 rubric weighted equally across correctness & logic (does it implement the spec?), code quality (naming, structure, readability), and edge-case coverage (does it handle boundary conditions?). Always produces a numeric score that the stop-check engine reads each round.
🔍
Critic
Given the Evaluator's score and the current code, the Critic performs a surgical analysis: not just "what's wrong" but "what specific changes would raise the score". It outputs prioritized, actionable change requests — the exact signal the Improver needs to make a meaningful next revision.
✨
Improver
Reads the current draft, the Evaluator's score, and the Critic's change requests and produces a fully revised implementation. The loop then returns to the Evaluator for re-scoring — the cycle continues until the stop condition fires (threshold ≥85 or score plateau). All history is threaded forward so the Improver can see what has and hasn't worked.
🏁
Final Reviewer
Activated once a stop condition fires. Receives the best scoring code, all round scores, and the stop reason. Produces a final polished version of the code with docstrings and comments, an executive summary, performance analysis, and ideas for extending the solution. Branched — never part of the improvement loop itself.
⚖️
Stop-Check Engine
After every Evaluator call, three checks run in order: (1) Threshold — if score ≥ 85, stop immediately. (2) Plateau — if score improved < 5 points for 2 consecutive rounds, stop (diminishing returns). (3) Hard cap — if round count hits 6, stop as a safety fallback. Whichever fires first is logged and displayed in the final summary as the exact stop reason.
