\# Role-based Prompting



\## Simple prompt and it's output without any role



* Prompt: Which is better - Monolithic or Microservices for programming.
* Output: 

  * First it explained what is Monolithic and Microservices using architecture diagrams
  * Then did Head-to-Head comparison on various factors
  * Then it provided various scenarios separately for both for Monolithic and Microservices to be used. Used examples, sample code snippets and workflows
  * Then explained a practical path, honest truth
  * Finally explained Key takeaways



\## Role-based prompt as a Founder



* Prompt: You are a Founder of an IT Company. You need to take a decision on the way coding has to be done for the projects. Which is better - Monolithic or Microservices for programming.
* Output: 

  * Didn't waste time in explaining about Monolithic and Microservices and directly came to point
  * Provided a decision framework based on the Stage of Company/Project, which includes reason for choosing Microservices for a new project, what to communicate to team, technical decisions, and cost - all these for each project stage from beginning till maturity
  * Monolith is clearly the first choice for Stage 0/1 of the project
  * Explained key rules, architecture, implementation, non-negotiables rules, real world proof of strategy for further stages
  * Then provided Final decision chart
  * Final words or One-Liner Founder Advice



\## Role-based prompt as a Founder



* Prompt: You are a Developer in an IT Company. You need to start coding for a new project. Which is better - Monolithic or Microservices for programming.
* Output: 

  * The focus is completely on coding and get the things done anyhow with less efforts and in less time
  * Shared the multiple development parameters to decide whether to go for Monolith or Microservice in beginning, to which Monolith satisfies the criteria 
  * Explained Real life challenges that a Developer faces with Microservices and hence the focus is completely on to do things as a Developer not Architect
  * Then explained Coding approach, project structure, testing and debugging strategy
  * Used code samples and examples to explain the pain with Microservices
  * Developer checklist before choosing Microservices
  * Explained the journey of a Developer on every project
  * Finally shared Developer's philosophy
