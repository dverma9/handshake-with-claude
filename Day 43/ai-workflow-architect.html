STAGE 01
Discovery & Planning
Define the product scope, gather stakeholder requirements, establish technical constraints, and produce a clear project charter before writing a single line of code.
⏱ 1–2 weeks 👥 Entire team + stakeholders Phase: Pre-development
🎯 Objectives
  • ▸ Define product vision, goals, and success metrics (KPIs)
  • ▸ Document functional and non-functional requirements
  • ▸ Identify stakeholders, user personas, and user journeys
  • ▸ Assess technical constraints and enterprise compliance needs
  • ▸ Produce project charter and initial backlog
✅ Tasks (click to complete)
  • Conduct stakeholder interviews (min. 3 sessions)
  • Define and document user personas
  • Write Software Requirements Specification (SRS)
  • Create initial user story backlog in Jira/Linear
  • Map compliance requirements (GDPR, SOC2, etc.)
  • Establish Definition of Done (DoD) and coding standards

🚫 Common Mistakes
✕Skipping non-functional requirements (security, performance SLAs) — these are critical in enterprise environments.
✕Gathering requirements from only one stakeholder group. Always include both business and technical representatives.
✕Creating an overloaded Phase 1 backlog. Small teams should scope MVP tightly — 6 core features maximum.
✕Ignoring enterprise compliance early. Retrofitting GDPR, SSO, or audit logging is extremely costly.

🚫 Common Mistakes
✕Using default change detection everywhere. Always use OnPush for smart/container components in enterprise apps — critical for performance.
✕Direct HTTP calls in components. All API calls must go through services — never in template or component directly.
✕Missing unsubscribe logic with RxJS. Use takeUntilDestroyed() or async pipe to prevent memory leaks.
✕No accessibility (a11y) from the start. Enterprise products must meet WCAG 2.1 AA — add aria labels and keyboard navigation early.

🚫 Common Mistakes
✕Business logic in @Controller methods. Controllers must only handle HTTP, never business rules — that belongs in @Service.

✕N+1 query problems with JPA. Always check generated SQL in dev and use fetch joins or projections for list endpoints.

STAGE 06
Frontend–Backend Integration
Connect the Angular frontend to the Spring Boot backend — wire up APIs, handle authentication end-to-end, real-time features, and cross-cutting concerns.
⏱ 2–3 weeks 👥 Full team Phase: Integration
✅ Tasks
  • Configure Angular HTTP interceptor (auth token + error handling)
  • Wire up login flow end-to-end (Angular → Spring Security → JWT)
  • Test all CRUD API endpoints through Angular UI
  • Implement real-time updates with WebSocket / Server-Sent Events
  • Handle pagination, sorting, and filtering end-to-end
  • Implement file upload/download if required
🔄 Auth Integration Flow
1. User submits credentials (Angular form)
2. POST /api/auth/login → Spring Security
3. Spring returns JWT access + refresh tokens
4. Angular stores JWT in memory (not localStorage)
5. HTTP Interceptor attaches Bearer token to all requests
6. 401 response → interceptor auto-refreshes token
7. Spring validates JWT on every protected endpoint
8. Angular guards protect routes by role/permission

STAGE 07
Testing & Quality Assurance
Establish a comprehensive testing strategy with unit, integration, and E2E tests for both Angular and Spring Boot to ship production-quality software.
⏱ Ongoing + 2-week sprint 👥 All developers Phase: QA
🔺 Testing Pyramid for Angular + Spring Boot
🎭 E2E Tests (Cypress) — 10%
Critical user flows: login, purchase, key workflows
🔗 Integration Tests (Spring @SpringBootTest) — 20%
API contracts, DB interactions, security filters
✅ Unit Tests (JUnit 5 + Jasmine) — 70%
Service methods, components, pipes, utilities — fast and isolated
✅ Tasks
  • Achieve 80%+ unit test coverage on Spring Boot services
  • Write @DataJpaTest and @WebMvcTest integration tests
  • Write Jasmine unit tests for Angular services and components
  • Write Cypress E2E tests for all critical user flows
  • Run performance tests with k6 or JMeter
  • Run OWASP ZAP security scan on API

💬 Prompt Examples
JUnit 5 Spring Boot Tests
Generate JUnit 5 unit tests for this Spring Boot service class. Include: happy path tests, edge cases, null input handling, and exception scenarios. Use Mockito to mock all @Autowired dependencies. Target 100% method coverage for the service layer. [paste your service class]
Cypress E2E Test

🚫 Common Mistakes
✕Testing implementation details instead of behavior in Angular. Test what the component does, not how.
✕Using @SpringBootTest for every test — it's slow. Use @WebMvcTest or @DataJpaTest slices for focused tests.
✕Writing E2E tests before unit tests are stable. E2E tests are expensive — use them for smoke tests only.
✕No test data strategy. Enterprise apps need DB reset between test runs — use Testcontainers + Flyway for clean state.

Deployment & DevOps
Ship the enterprise application to production with containers, CI/CD pipelines, cloud infrastructure, monitoring, and zero-downtime deployment strategies.
⏱ 1–2 weeks 👥 Tech lead + DevOps Phase: Production
✅ Tasks
  • Write production-optimized Dockerfiles (multi-stage builds)
  • Set up Kubernetes manifests or Docker Compose for production

☁ Cloud Deployment Options
☁ AWS — EC2 / ECS Fargate + RDS PostgreSQL + ElastiCache Redis. Best for enterprise with existing AWS contracts.
☁ Azure — App Service / AKS + Azure DB for PostgreSQL. Best for Microsoft-stack enterprises.
☁ GCP — Cloud Run + Cloud SQL + Memorystore. Best for containerized workloads with low ops overhead.
🐳 Self-hosted — Docker Swarm + Traefik on VPS. Lowest cost for small enterprise teams.
